1️⃣ Payment + reservations/services.py

Paling relevan dengan bisnis hotel. Menunjukkan konsep Single Gate untuk mengubah status.

📍 Lokasi

  • reservations/models.py (class Payment)
  • reservations/services.py (service layer)

🎯 Pilar Utama

ENCAPSULATION ABSTRACTION

Penjelasan

  • Encapsulation: Semua perubahan status pembayaran (UNPAID → PENDING_VERIFICATION → VERIFIED/REJECTED, refund) wajib lewat reservations/services.py. Ada __is_verifiable() sebagai private method.
  • Abstraction: View, Admin, dan Webhook cukup memanggil submit_payment_proof(), verify_payment(), request_refund(), complete_refund(). Mereka tidak perlu tahu detail select_for_update(), locking, atau sinkronisasi Booking↔Payment.

Contoh Kode

# reservations/models.py
class Payment(BaseTransaction):
    # ...
    def __is_verifiable(self):
        """Private method: hanya bisa diakses dari dalam class ini"""
        return self.status_pembayaran in (self.PENDING_VERIFICATION, self.REJECTED)

    def verifikasi_pembayaran(self, is_approved: bool, actor=None, reason=''):
        from .services import verify_payment
        # Wrapper ke service layer (single gate)
        updated = verify_payment(self, approved=is_approved, actor=actor, reason=reason)
        return updated

📍 Lokasi

🎯 Pilar Utama

ENCAPSULATION POLYMORPHISM

Penjelasan

  • Encapsulation: _can_transition() (protected) + transition_to() jadi SATU-SATUNYA PINTU untuk mengubah status. Status order tidak boleh diubah langsung dengan order.status = ...
  • Polymorphism: Transisi bergantung pada fulfillment. DELIVERY → harus berakhir di DELIVERED. PICKUP → harus berakhir di READY. Satu method, perilaku validasi berbeda tergantung objek.

Contoh Kode

# chatbot/models.py - ENCAPSULATION + POLYMORPHISM
def _can_transition(self, new_status):
    """Protected: validasi transisi"""
    allowed = self.ALLOWED_TRANSITIONS.get(self.status, ())
    if new_status not in allowed: return False
    if new_status == self.STATUS_READY and not self.is_pickup: return False
    if new_status == self.STATUS_DELIVERED and self.is_pickup: return False
    return True

def transition_to(self, new_status, actor=None, note=''):
    """SATU-SATUNYA cara resmi mengubah status pesanan"""
    if not self._can_transition(new_status):
        return False
    old_status = self.status
    self.status = new_status
    self.save(update_fields=['status', 'updated_at'])
    ServiceOrderStatusLog.objects.create(order=self, status=new_status, note=note, changed_by=actor)
    return True

3️⃣ Payment Processor - Inheritance + Polymorphism + Abstraction

Paling eksplisit. Hampir persis seperti contoh perbankan di materi perkuliahan.

📍 Lokasi

  • reservations/payment_processors/base.py
  • reservations/payment_processors/manual_transfer.py
  • reservations/payment_processors/gateway.py

🎯 Pilar Utama

INHERITANCE POLYMORPHISM ABSTRACTION

Penjelasan

  • Abstraction: BasePaymentProcessor(ABC) mendefinisikan kontrak charge(), refund(), get_method_name() tanpa implementasi detail. Caller hanya tahu interface.
  • Inheritance: ManualTransferProcessor dan GatewayPaymentProcessor mewarisi BasePaymentProcessor. Relasi "adalah jenis dari" (is-a).
  • Polymorphism: Satu interface, dua implementasi berbeda. Bisa dipanggil secara polimorfis dengan processor.charge(booking, amount) tanpa peduli tipe konkret objeknya.

Contoh Kode

# reservations/payment_processors/base.py
from abc import ABC, abstractmethod

class BasePaymentProcessor(ABC):
    """Kontrak untuk semua pemroses pembayaran"""
    @abstractmethod
    def charge(self, booking, amount): pass
    
    @abstractmethod
    def refund(self, payment, amount): pass
    
    @abstractmethod
    def get_method_name(self): pass

# reservations/payment_processors/manual_transfer.py
class ManualTransferProcessor(BasePaymentProcessor):
    def charge(self, booking, amount):
        return {"method": "MANUAL_TRANSFER", "status": "PENDING_VERIFICATION"}
    
    def refund(self, payment, amount):
        from ..services import request_refund
        request_refund(payment, reason="Refund via manual transfer")
        return {"method": "MANUAL_TRANSFER", "status": "REFUND_PENDING"}
    
    def get_method_name(self): return "Transfer Bank Manual"

# reservations/payment_processors/gateway.py
class GatewayPaymentProcessor(BasePaymentProcessor):
    def charge(self, booking, amount):
        return {"method": "GATEWAY", "status": "AWAITING_PAYMENT"}
    
    def refund(self, payment, amount):
        return {"method": "GATEWAY", "status": "REFUND_INITIATED"}
    
    def get_method_name(self): return "Payment Gateway"
